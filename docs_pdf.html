1. Executive Summary & System Purpose

The EquipmentsDekho Partners Brand Portal is an enterprise-grade B2B Customer Relationship Management (CRM) and operations application built for commercial equipment manufacturers, brand principals (such as JCB, Caterpillar, Tata Hitachi, etc.), and authorized regional distributors.

It captures inbound customer inquiries and equipment quotation requests directly from the EquipmentsDekho marketplace and provides multi-tier sales routing, automated workload-balanced dispatching, live Sub-Admin account capacity tracking, and strict territorial access controls across all Indian states and cities.

2. High-Level Architectural Overview

The application follows a decoupled Single Page Application (SPA) architecture communicating with a centralized RESTful API backend:

Core System Topology
1. Client Tier: React 19 SPA (Vite 8, Tailwind CSS v4)BROWSER
Hosts UI components, React Context state providers, and client-side routing guards.
↓ HTTP / REST (Bearer JWT Auth)
2. Network Layer: Axios Client with InterceptorsHTTP
Injects authorization tokens, serializes multipart uploads, and intercepts HTTP 401/403/422 responses with deduplicated toasts.
↓ JSON / Multipart Payloads
3. Remote API Backend: EquipmentsDekho ServicesAPI SERVER
Handles persistent data stores, quotation requests, dynamic permission definitions, and live sub-admin account quotas.

5. Authentication, Session & Security Model

Authentication is enforced via a JWT bearer token model. Role normalization strictly prevents accidental privilege escalations:

Step 1: Credential SubmissionPOST
User submits username and password via POST /premium-brand-login.
↓
Step 2: Token Issuance & Role NormalizationSECURITY
Backend responds with JWT token and user record. roleUtils.normalizeUserType() validates user_type. Unknown roles are immediately rejected.
↓
Step 3: Storage & Interceptor InjectionSTORAGE
Token is stored in localStorage. The Axios request interceptor attaches Authorization: Bearer <token> to all subsequent requests.
↓
Step 4: Startup Session Validation & 401 GuardVALIDATION
On page reload, fetchProfile() calls POST /profile. Any 401 response wipes credentials and forces redirection to /login without infinite reload loops.
Critical Security Implementation Rule
The application strictly refuses to default missing or malformed user roles to Admin. If a user record lacks an explicit user_type: "admin" or "sub_admin", the normalized role evaluates to null, and protected route access is immediately blocked.

6. Multi-Tier Role-Based Access Control (RBAC) & Governance Model

The system enforces strict operational separation between two fundamental roles:

Dimension Brand Admin (Principal) Sub-Admin (Regional Operator)
Geographic Scope All Indian States & Cities (Nationwide visibility). Strictly restricted to assigned States & Cities.
Navigation Menus Loads dynamic CRM modules plus full Operations suite (Sub-Admins, Reports, Profile). Dynamically resolved strictly from POST /sub-admin-sidebar response.
Team Management Can create Sub-Admins, inspect capacity quotas, and toggle permission access. Zero access to team management pages.
Lead Assignment Can assign to any operator, trigger auto-assignment, or confirm out-of-territory overrides. Can only manage leads assigned to them or within their territory boundaries.
Reporting & Analytics Full access to state-wise demand distribution and operator conversion metrics. No access to executive reporting suite.

Master Admin vs. Partner Brand Admin Governance Model

An essential architectural boundary is maintained between Master Admin (Equipments Dekho Super Admin) and Partner Brand Admin (e.g., JCB Admin):

  • Permission Definitions Governance (Master Admin Only): Master Admin alone possesses authority to create, edit, or delete global permission definitions. Individual brand admins cannot alter the permission catalog. Consequently, the global /permissions tab is disabled in Partner Admin and automatically redirects to /sub-admins.
  • Permission Assignment Governance (Partner Brand Admin): Brand Admins manage Sub-Admin access strictly using Enable / Disable toggle switches (calling POST /add-role-permission and POST /delete-role-permission). Permissions are never deleted from the system, only toggled on or off for the selected Sub-Admin.

7. Dynamic Navigation & Route Guard Engine

Instead of hardcoding client-side routes, navigation items are built dynamically from server responses:

  • PrivateRoute: Ensures a valid token and recognized role exist in session. If absent, redirects to /login.
  • PublicRoute: Prevents authenticated users from seeing guest pages (redirects to /dashboard).
  • PermissionRoute: Evaluates if the authenticated user possesses the specific module permission. Supports an adminOnly prop that immediately blocks Sub-Admins.
  • PermissionGate: In-component conditional wrapper that renders buttons or actions only if the user has granular action permissions (e.g. quotes:export).

8. CRM Operations Engine & Business Workflows

8.1 Leads Management & Unified Pipeline (AllLeads.jsx)

The master leads register aggregates all prospective equipment buyers into a high-performance interactive table featuring:

  • Tabbed Views: All Leads (complete visible dataset), Unassigned Leads (inbound queue requiring action), and My Leads (leads assigned to the logged-in operator).
  • Multi-Field Search: Real-time filtering across customer name, phone, lead code, machine interest, city, and state.
  • Status Lifecycle: Tracks leads through New → Assigned → Contacted → Follow-up → Quote Sent → Won / Lost.

8.2 Customer Enquiries Workflow (CustomerEnquiry.jsx)

Communicates with POST /premium-brand-quotes-enquiry. Features pagination controls, quick phone-calling triggers (tel:), and one-click lead drawer inspection.

8.3 Feature Equipment Quotation Requests (FeatureEquipmentQuotes.jsx)

Communicates with POST /get-feature-equipment-quotes. Enriches product-specific quotation requests with CRM deal stages and pricing discussions.

9. Geographic Territory Management & Workload Auto-Assignment Engine

Lead routing is governed by an automated, workload-aware decision engine implemented in utils/accessRules.js:

Auto-Assignment Logic Flow
1. Extract Lead Location: Identify the target state and city from inbound inquiry data.
2. Query Candidate Pool: Scan all Sub-Admins in the current brand account.
3. Evaluate Operational Eligibility: Candidate must meet three conditions:
• Account status is active
• Has view AND update permissions for this CRM type (e.g. leads:view + leads:update)
• Territory coverage: Operator's assigned territory state matches lead state, AND (cities include "ALL" OR lead city).
4. Workload Balancing Calculation: For all eligible candidates, compute active open burden: 
openCount = leads.filter(l => l.assigned_to === member.id && l.status !== "won" && l.status !== "lost").length
5. Final Execution: Automatically assign the lead to the operator with the minimum active count. Record the automated routing decision in the lead activity timeline.

Admin Manual Territory Override

If a Brand Admin manually assigns a lead to an operator whose territories do not cover the lead's state/city, the system displays an Override Confirmation Dialog. Upon confirmation, the assignment proceeds and is logged with a permanent audit record:

"Admin territory override assignment by [Admin Name]. Reason: Out-of-territory manual assignment override confirmed."

10.4 Sub-Admin Permission Enable/Disable Toggle Architecture

In SubAdminPermissions.jsx, permissions are managed through a clean ON / OFF toggle table (PermissionTable.jsx):

  • Live Definitions: Fetched via POST /get-premium-brand-permissions.
  • Assigned Permissions: Loaded via POST /sub-admin-sidebar using the Sub-Admin's role_id.
  • Toggle Switches: Clean switches for every module permission. Permissions cannot be deleted from this screen, only toggled ON or OFF.
  • Differential API Synchronization: When saved, turned-off permissions call POST /delete-role-permission with { role_id, permission_name }, and turned-on permissions call POST /add-premium-brand-role-permission.

11. Reusable Enterprise Form & Modal/Drawer System

The portal provides a centralized, reusable form and dialog architecture across all create/edit workflows:

11.1 useAppForm Hook Architecture (hooks/useAppForm.js)

A unified form management hook providing:

  • Controlled Values & Validation: Declarative validation rules (required, email, phone, minLength, maxLength, pattern, and custom functions).
  • Real-Time Error Clearing: Editing an input immediately clears field-level errors and top-level error banners.
  • Auto-Focus First Error: Automatically focuses the first invalid DOM input on failed validation.
  • Submission Protection: Prevents duplicate submissions while async requests are in progress.

11.2 Declarative Form & FormField Components

  • Form.jsx: Schema-driven grid container supporting 1-col or 2-col responsive layouts, top-level error alert banners, and submit button states.
  • FormField.jsx: Polymorphic field renderer wrapping labels, required asterisks, helper text, and input controls.
  • PasswordInput.jsx: Controlled password field with secure reveal toggle (Eye / EyeOff) and mouse-down focus retention.

11.3 Root-Cause Resolution of Global Input Focus Stealing

Focus Bug Diagnostic & Architecture Fix
Root Cause: In Modal.jsx and Drawer.jsx, the focus management useEffect depended on inline callback props (such as onClose). Each typed character updated parent state and re-rendered the parent with a new function reference. This re-ran the focus effect on every keystroke, which queried container.querySelector('button...') and focused the header close X button.

Resolution Applied:
• Restricted effect execution strictly to [isOpen] transitions.
• Synchronized callback references safely inside useEffect outside the render cycle.
• Targeted editable form inputs (input:not([disabled]), textarea, select) rather than generic buttons.
• Added onMouseDown={(e) => e.preventDefault()} to end-action buttons (password eye toggle, search clear).

12. Global Dark Mode Table Architecture & Responsive Layout

All tabular views (DataTable.jsx, PermissionTable.jsx, and CRM page tables) implement unified dark theme styling:

  • Dark Header Tokens: Header cells use bg-slate-50 dark:bg-slate-800, text text-slate-700 dark:text-slate-200, and borders border-slate-200 dark:border-slate-800, eliminating all hardcoded white backgrounds.
  • Sticky Headers with Backdrop Blur: Sticky headers maintain opaque backgrounds (bg-slate-50/95 dark:bg-slate-800/95 backdrop-blur-xs) with z-10 layering to prevent content bleed during vertical scrolling.
  • Responsive Overflow Container: Tables are wrapped in overflow-x-auto w-full min-w-0 containers, preventing horizontal viewport clipping and preserving search controls on mobile/tablet viewports.

16. End-to-End Sequence & Data Flow Diagrams

16.1 Sub-Admin Creation with Real-Time Quota Validation

1. Brand Admin navigates to /sub-admins. UI calls POST /get-subadmins with brand ID.
2. Server returns capacity metrics: allowed_sub_admins: 3, current: 2, remaining: 1. UI enables "Add Sub Admin" button.
3. Admin clicks "Add Sub Admin". Slide-over Drawer opens with Assigned Brand badge and "1 slot remaining" indicator.
4. Admin submits form. useAppForm validates required fields, email, phone, and password length.
5. Client dispatches POST /create-premium-brand-sub-admins with 9 parameters via multipart form data.
6. Server creates account and responds with success message and new Sub-Admin ID.
7. Drawer closes, toast notifies admin, and table re-fetches. Capacity updates to 0 slots remaining, disabling the button.

16.2 Sub-Admin Permission Enable/Disable Toggle Sequence

1. Admin selects a Sub-Admin operator on /sub-admins?view=access.
2. UI queries dynamic definitions (POST /get-premium-brand-permissions) and assigned permissions (POST /sub-admin-sidebar).
3. PermissionTable renders toggle switches for each capability (e.g. Customer Enquiry: ON, Quotes: ON, Leads: OFF).
4. Admin toggles "Leads" to ON and "Quotes" to OFF, then clicks "Save Permissions".
5. Service calls POST /delete-role-permission for "Quotes", then POST /add-premium-brand-role-permission for "Customer Enquiry" and "Leads".
6. Success toast is displayed, dirty state clears, and permissions are instantly synchronized.

18. Production Deployment & Strategic Recommendations

  1. Route-Level Code Splitting (React.lazy): Split heavy pages (CustomerEnquiry.jsx, FeatureEquipmentQuotes.jsx, CRMReports.jsx) using dynamic imports to optimize bundle delivery.
  2. IndexedDB Offline Caching: Integrate Dexie.js for client-side CRM caching so field operators can view lead contact details during temporary network outages.
  3. Real-Time SSE / WebSocket Alerts: Implement Server-Sent Events to automatically trigger new lead notifications without requiring manual table refreshes.
  4. Automated E2E Suite: Automate critical test flows (Sub-Admin creation, capacity quota decrement, permission toggles).
